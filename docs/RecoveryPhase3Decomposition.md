# Фаза 3 — декомпозиция на минимальные итерации

Контекст: E2E-набор (3.1) на MiniC вскрыл 3 системных бага движка восстановления.
Каждый баг — отдельная минимальная итерация с чёткой зависимостью. Порядок запускается
от минимальных зависимостей.

## Установленные факты (эмпирика, пробы `ProbeTests.cs`)

Вход-репро краша: **хвостовой мусор в истинном EOF** — `int foo() { return 0; } ###`.
Порядок попыток на e=24: `S0(1), 9×S1(2–10), S3(11), S4(12), S5(13)`.

| Бюджет | Результат |
|---|---|
| 10 | без краша: `Success@24, ErrorInfo=24` (только S0+9×S1, восстановления нет) |
| **11** | **детерминированный stack overflow** (3/3) — 11-й кандидат (S3) |
| 12–16 | stack overflow |

Механизм краша: S3 (терминатор=EOF) ставит абсорбер `###`→`int` в (24, int), ре-парсинг
даёт прогресс e 24→27(=EOF) → кандидат принят → на следующей итерации e=EOF candidates
генерируются заново → **бесконечная рекурсия `ParseSeq → ParseSeq`** → переполнение стека.

Доп. факты:
- **Пер-позиционный бюджет не ограничивает суммарную работу**: каждое новое e получает
  свежий `attempts` (Parser.cs:385-389). Глобально ограничивает только `MaxRecoveryIterations`.
- **Мусор МЕЖДУ функциями** (`... } ### int bar() ...`): S2 resync принимается (e 24→32→36),
  но до EOF не доходит (`ErrorInfo=36`) — абсорбер глотает `### ` как `int`, и настоящий
  ключ `int` съедается `Ident` (рассинхрон). Краша нет (бюджет ≤14).
- **S5 для true-EOF генерируется** (снимок на e снимается при mismatch `int` vs `###`) —
  утверждение субагента 3.1 «snapshot null → S5 не генерируется» неверно.

## Итерации

### 3.0a — Stack guard (без зависимостей) → **СНАЧАЛА**
- **Цель:** убрать stack overflow (безопасность). Рекурсия во время recovery re-parse
  не должна ронять процесс.
- **Фикс (основной):** guard глубины рекурсии парсера — счётчик (incr на входе в рекурсивный
  parse, decr в finally); при превышении лимита текущий путь возвращает `Failure`
  (аборт ветки). Лимит — безопасный для легитимных глубоких разборов (полный тест-набор
  — проверка).
- **Фикс (доп, по желанию):** ранний стоп цикла, если `e == input.Length` (за EOF
  восстанавливать нечего) — точечно бьёт по корню.
- **Скоуп:** `ExtensibleParser/Parser.cs` (+ возможно поле-счётчик).
- **Верификация:** (1) тест-репро `int foo() { return 0; } ###` + `MaxRecoveryAttemptsPerPosition=11`
  **не крашится** (возвращает результат); (2) полный ParserTests зелёный; (3) сборка 0/0.
- **Зависимости:** нет. **Размер:** S–M.
- **Подшаги:** 3.0a.1 failing-тест-репро → 3.0a.2 guard → 3.0a.3 верификация.

### 3.0b — Бюджет: достижимость S2/S3/S5 (зависит от 3.0a)
- **Цель:** resync/panic/trailing-кандидаты (ранг 2/3/5) должны допускаться до их попытки,
  а не умирать от S1-шума (до `|FollowSet|+2` кандидатов).
- **Варианты фикса:** (a) поднять дефолт `MaxRecoveryAttemptsPerPosition` (3→16);
  (b) per-rank бюджет (лимит на ранг, а не на позицию суммарно); (c) кап числа S1-кандидатов.
  Выбор — после 3.0a (краш уйдёт, можно безопасно поднимать). Рекомендуемый: **(b) per-rank**
  (не раздувает суммарную работу, гарантированно даёт шанс каждому рангу) либо (a) как самый
  простой.
- **Скоуп:** `Parser.cs` (цикл/лимит) и/или `RecoveryEngine.cs` (кап S1).
- **Верификация:** (1) true-EOF (`... ###`) с дефолтным бюджетом доходит до S3/S5
  (диагностика Skipped/Trailing появляется, краша нет — 3.0a на месте); (2) between-функции
  доходит до S2 (Skipped-диагностика); (3) полный ParserTests зелёный.
- **Зависимости:** 3.0a. **Размер:** S.

### 3.0c — Размещение абсорбера S2/S3/S5 (зависит от 3.0a, 3.0b)
- **Цель:** абсорбер мусора должен ставиться на уровне цикла/Seq (мусор между/после
  итераций цикла глотается целиком, следующая итерация стартует с чистого терминала),
  а не слепо на упавшем терминале верхнего кадра. Сейчас: `### `→`int` в (24,int)
  рассинхронизирует разбор (Ident съедает настоящий `int`).
- **Скоуп:** `RecoveryEngine.cs` (логика абсорбера в `GenerateS2`/`GenerateS3`/`GenerateS5`,
  `AddResyncCandidate`).
- **Верификация:** (1) true-EOF → `Success@EOF` + Skipped/Trailing-диагностика + абсорбер
  в дереве (IsRecovery); (2) between-функции → `Success@EOF` (bar разобран целиком);
  (3) полный ParserTests зелёный (в т.ч. AnchorResyncTests, CandidateGenerationTests).
- **Зависимости:** 3.0a, 3.0b. **Размер:** M (дизайн-изменение).
