# Recovery Improvement Plan — Progress: A10 + A11

Sub-point: A10 (token-wise scan in S3/S6) + A11 (filter catch-all regex terminals out of S3/S6 stop-sets).

## Intent / approach

- **A11**: Add a private static readonly fixed criterion in `RecoveryEngine` — the set of terminal `Kind` strings treated as catch-all regex (`"Identifier"`, `"Ident"`). Apply this filter at all three stop-set insertion sites: `terminators` union in `GenerateS3`, `terminators`/anchor-First union in `GenerateS6`, and inside `AddSuffixObligations`. Comment stating the fixed criterion (Literal, numeric/real/hex/binary/char/string literals, punctuation, Trivia NEVER filtered; when in doubt, do not filter).
- **A10**: In the S3 scan loop and the S6 scan loop, when the stop-set check at position `s` found NO match, compute the longest `TryMatch` length `L` of ANY grammar terminal at `s`; if `L > 0`, `s += L - 1; continue` (jump over the whole token). Enumerate grammar terminals via a local helper that walks the rule set (Rules + TDOPP rules) once per `GenerateS3`/`GenerateS6` call, dedup via `TerminalComparer.Instance`, exclude `EofTerminal`/`EpsilonTerminal`. In S3 route through the existing `Match(term, pos)` local (matchCache reuse); in S6 plain `TryMatch` loop.
- Preserve unchanged: `parser.NoteS3ScanPosition()`, bracket-counter switch at loop entry, trivia jump, cost-sorted `ordered` stop-set check with depth filter, EOF check, `foundS`/`foundT` semantics, everything after the loops (candidate construction, ranks, diagnostics).
- Do NOT change: `Generate`/`GenerateS3`/`GenerateS6` signatures, candidate ordering/ranks, S1/S1b/S2/S4/S5, `FollowSetCalculator.cs`, `Parser.cs`, `Parser.Recovery.cs`.
